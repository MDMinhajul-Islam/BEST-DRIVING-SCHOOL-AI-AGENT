# Variable registry — MVP versus Phase D

Create 21 CORE definitions for the first build; do not ask for every field on every call. The other 48 concepts stay documented here. CONDITIONAL variables are enabled only for their pathway; absence does not permit guessing. Server-only fields are not LLM extraction fields. Eight aliases/derived fields are omitted, not deleted from Phase D.

## Exact initial values and writers

All facts/IDs/prices/dates unset unless supplied by a reviewed tool/configuration or explicitly reported. primary_intent=unknown, student_or_parent=unknown, road_test_eligibility=unknown, support_category=unknown, booking_status=NO_PACKAGE; transient text lists unset, not cached example times. Number fields have no guessed default. session_plan, available_slots and selected_slot are Text holding compact sanitized JSON when a tool supplies them; parse/validate on server, not arbitrary JSON from the caller. preferred_date is ISO text; resolve relative dates using owner-confirmed school timezone or ask an explicit date; never assume timezone.

Nodes 01–08 use the built-in Extract Dynamic Variable tool for their caller-reported fields. Prompt instructions alone do not persist dynamic variables. Use prompt-based transition conditions for meaning learned in conversation, not equation conditions over nonexistent variables. Tool-backed fields require approved response binding: package_id/name/price from catalog acceptance, session count/plan from known rule, slots and appointment/status from sanitized tool results. Do not attach appointment_id, confirmed booking_status or raw slot lists to free-form extraction. Retell extraction supports Text/Number/Enum/Boolean; no native array is assumed.
