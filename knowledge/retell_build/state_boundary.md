# State boundary

| Conversation | Backend/configuration |
| --- | --- |
| Reported age, credential/education stage, goal | Scoped identity/verification/authentication tokens |
| Canonical selected package and sourced display price | Authoritative native package/location/resource IDs and source snapshots |
| Preferences and sanitized returned choices | Freshness, resource/duration checks, timezone, capacity |
| Display appointment reference/status after explicit tool result | Versions, idempotency, request IDs, pending action and reconciliation |
| Minimal support issue and staff reason | Account records, payment/refund lifecycle and authorization |

No secrets in Retell dynamic variables, transcript arguments, metadata or debug output. Retell logs expose dynamic variables; keep only necessary sanitized display results. fixed mode belongs to builder configuration and server permission checks, not caller-controlled state. Conditional contact is deferred until a real consented intake exists.

MVP uses the 21 CORE definitions and transcript context. Multi-session accumulated selections live server-side; model sees current choices/progress. Existing mock has four synthetic one-hour fixture slots and no real lesson accounting. Duration-aware fixtures and an approved authenticated HTTP wrapper are prerequisites for a faithful session-duration demo, not extra Retell nodes. No wrapper is deployed today.

Production Extension retains concurrency/version checks, durable deduplication, unknown-write reconciliation, verified customers and resources, remaining-hours accounting, confirmed native mappings, lifecycle/payment/refund policy and privacy/retention controls. They remain required backend work even though absent from conversational MVP state. Do not weaken these controls to reduce variable count.
