## Modes and private configuration

Default `BOOKING_MODE=mock` uses durable synthetic fixtures. A provider key alone never switches modes. Set `BOOKING_MODE=calcom_test`, a private `CALCOM_API_KEY`, and the three IDs for real demo-provider reads. Leave `CALCOM_WRITE_ENABLED=false` during configuration review. To run explicitly approved synthetic booking tests, set it to `true` and configure `CALCOM_TEST_EMAIL` privately with the supplied test address. Attendee names must start with `BDS AI TEST`; Cal writes only accept that configured email. Never place keys or the email in committed files, tool arguments generated by the model, or browser code.

`calcom_live` additionally requires `CALCOM_LIVE_ENABLED=true`. It remains a Cal.com demo provider, not school production. Production school writes remain blocked in the existing school adapter. Do not interpret the name as a deployment approval.

Availability calls use [GET slots](https://cal.com/docs/api-reference/v2/slots/get-available-time-slots-for-an-event-type), version `2024-09-04`, explicit UTC date bounds, America/Chicago, and range format. Booking [create](https://cal.com/docs/api-reference/v2/bookings/create-a-booking), [lookup](https://cal.com/docs/api-reference/v2/bookings/get-a-booking), [reschedule](https://cal.com/docs/api-reference/v2/bookings/reschedule-a-booking), and [cancel](https://cal.com/docs/api-reference/v2/bookings/cancel-a-booking) use version `2026-02-25`. Every request uses the fixed official API origin and server-side Bearer authentication; redirects are disabled. Version headers are endpoint-specific and pinned in code.

## Validation sequence

1. Run the test suite and mock workflow first.
2. Configure and review event IDs and calendar settings; keep writes disabled while checking real availability through the authenticated wrapper.
3. After explicit demo-test enablement, select only returned opaque slots. Run a single road-test create, find, reschedule to another returned slot, and cancel. Check Cal.com independently after each operation.
4. Test an adult multi-session package, then a teen plan including its 60-minute remainder. All selections are validated before any writes, but independent provider writes are not atomic.

Only provider status `accepted` confirms a session. Pending, rejected, missing identifiers, malformed responses, timeouts, and partial packages cannot confirm the entire package. Partial and uncertain outcomes retain durable locks. Staff must inspect the provider and SQLite ledger, reconcile each session, back up the database, and deliberately repair the corresponding action/lock state before any new attempt. There is no automatic rollback, retry, lock expiry, reconciliation endpoint, or refund action. Do not delete the ledger to bypass uncertainty.

Five adult plans use their verified purchased minutes; both known teen plans are 120/120/120/60. Road-test-only uses 30. Practice + test and PTDE remain staff review because their required allocation is unresolved. Online self-paced courses need no appointment; classroom and observation scheduling are outside this adapter.
